# Тестер компонентов крыла БПЛА

Тестер предназначен для проверки отдельных компонентов крыла беспилотного летательного аппарата на базе Arduino, экрана и кнопочного меню.

## Цель первой версии

Создать автономное устройство, которое позволяет оператору вручную выбирать и запускать отдельные тесты, видеть их состояние и результат на экране, а также безопасно завершать тест.

## Состав первой версии

В первую версию входят три независимых теста. Доступная автоматическая диагностика проводки зависит от интерфейса узла: I²C-датчик можно проверить обменом, а обычную трёхпроводную серву — только подачей команды с визуальным контролем.

1. **Сервопривод KST X10 V8.0** — универсальная безопасная команда `1500 → 1400 → 1600 → 1500 мкс` с визуальным подтверждением оператора. Тестер не использует понятия левого/правого крыла: он выдаёт только абсолютные PWM-импульсы. У этой трёхпроводной сервы нет обратной связи в тестер, поэтому автоматически доказать целостность проводов или физическое движение нельзя.
2. **Датчик давления трубки Пито Matek ASPD-4525** — проверка доступности по I²C и отображение дифференциального давления/расчётной воздушной скорости.
3. **Подключение к LoRa-модулю** — проверка целостности его проводки, факта подключения и доступности модуля для контроллера, например через инициализацию и диагностический обмен с модулем. Проверка полноценного радиообмена в первой версии не выполняется.

Тесты запускаются отдельно: одновременный запуск нескольких тестов в первой версии не требуется.

## Интерфейс оператора

- При включении отображается стартовый экран и доступ в главное меню.
- Главное меню содержит три теста и пункт выхода/возврата.
- Навигация выполняется кнопками.
- На экране отображаются выбранный тест, текущий этап, измеренные или диагностические значения, результат и понятное сообщение об ошибке.
- Для потенциально опасных или механически активных операций требуется подтверждение оператора.
- Тест можно остановить штатной кнопкой отмены или возврата.

## Функциональные требования

- Контроллер должен запускать каждый тест независимо от остальных.
- Перед запуском теста система должна выполнить базовую проверку доступности требуемого компонента, если это возможно.
- Результат каждого теста должен иметь как минимум состояния: `не запущен`, `выполняется`, `успешно`, `ошибка`, `отменён`.
- Ошибки должны обрабатываться без зависания меню и без необходимости немедленной перезагрузки устройства.
- После завершения теста оператор должен иметь возможность вернуться в меню и запустить другой тест.
- Для теста сервопривода должна быть предусмотрена безопасная остановка и ограничение тестового движения.
- Для теста Matek ASPD-4525 отображаются дифференциальное давление и расчётная воздушная скорость.
- Диагностика не должна заявлять автоматическую проверку цепей, которую аппаратно невозможно выполнить без дополнительных измерительных входов.
- Для проверки LoRa-модуля результат должен отражать именно подключение/доступность модуля, а не качество радиоэфира.

## Ограничения первой версии

В первую версию **не входят**:

- измерение потребляемого тока;
- проверка радиообмена LoRa между двумя устройствами;
- выбор конкретной распиновки;
- выбор конкретной модели экрана и LoRa-модуля;
- выбор конкретных библиотек;
- автоматическое сохранение результатов во внешнюю память или передачу результатов по сети;
- одновременное выполнение нескольких тестов.

## Требования к проектированию

- Архитектура должна позволять добавлять и изменять тесты без переписывания всего интерфейса.
- Аппаратно-зависимые части должны быть отделены от логики меню и сценариев тестирования.
- Все значения, зависящие от модели компонента, должны быть вынесены в конфигурацию после согласования аппаратной части.
- Нельзя окончательно фиксировать распиновку и библиотеки до уточнения моделей компонентов и экрана.
- При проектировании необходимо учитывать безопасные уровни напряжения, общую землю, защиту входов и механические ограничения сервопривода.

## Предварительно согласованные решения

- Целевая платформа — Arduino Nano-совместимая плата на ATmega328P, 5 В / 16 МГц, с micro‑USB и USB–UART семейства CH340. Для IDE базовая цель — `Arduino Nano`; при необходимости используется вариант старого загрузчика.
- Для меню предварительно используются четыре кнопки без фиксации: `Вверх`, `Вниз`, `ОК` и `Назад/Отмена`. Это минимальный практичный набор для понятной навигации и отмены теста.
- Тестируемые узлы должны запитываться от тестера через подключаемые штатные разъёмы, чтобы оператор мог подключить узел и запустить проверку без отдельного источника питания.
- Проверка каждого узла должна давать максимально доступный признак базовой работоспособности: обмен I²C для датчика, выполнение PWM-сценария и визуальное подтверждение для сервы.
- Проверка LoRa в первой версии выполняется как проводная проверка связи между Arduino и модулем, эмулирующая подключение к бортовой системе. Радиообмен между двумя LoRa-устройствами не проверяется.
- Для OLED предварительно рекомендуется интерфейс I2C: при одном экране он обычно требует меньше проводов и оставляет больше выводов Arduino Nano для тестируемых узлов. Окончательное решение принимается после уточнения модели экрана и его логических уровней.

## Открытые вопросы перед выбором аппаратной реализации

1. Подтверждено: Arduino Nano-совместимая плата на ATmega328P, 5 В / 16 МГц, micro‑USB, USB–UART семейства CH340.
2. Какая модель OLED, разрешение, рабочее напряжение и требуемая ориентация? Подтвердить выбор I2C или SPI после этого.
3. Подтвердить расположение четырёх кнопок: `Вверх`, `Вниз`, `ОК`, `Назад/Отмена`.
4. Подтверждено: KST X10 V8.0, питание 4,8–8,4 В; первый тестовый диапазон 1400–1600 мкс.
5. Подтверждено: Matek ASPD-4525, I²C `0x28`, питание 4–5,5 В, диапазон ±1 PSI.
6. Какие именно штатные разъёмы и линии доступны для каждого узла? Для первой версии достаточно проверки базовой работоспособности узла.
7. Какая модель LoRa-модуля и какой проводной диагностический обмен считать успешным подключением к Arduino?
8. Подтверждено: тестер питает подключённые узлы через штатные разъёмы. Нужно уточнить максимальные токи и допустимые напряжения после выбора моделей.
9. Журналирование, серийный номер и экспорт результатов пока не нужны.

## Критерии готовности первой версии

Первая версия считается готовой, если на согласованном наборе компонентов оператор может через кнопочное меню отдельно запустить все три теста, увидеть ход и итог, штатно отменить тест, получить понятное сообщение при недоступном или неисправном компоненте и вернуться в меню без перезагрузки устройства. Для сервы оператор визуально подтверждает движение; измерение тока и проверка радиообмена LoRa отсутствуют.
