# Подтверждённые компоненты и подключение

## Контроллер тестера

Используется **Arduino Nano-совместимая плата на ATmega328P**, с micro‑USB и USB–UART-преобразователем семейства CH340 (не оригинальная плата Arduino Nano). Форм-фактор и распиновка совместимы с классической Arduino Nano 5 В / 16 МГц; в Arduino IDE следует выбрать `Arduino Nano`, процессор `ATmega328P` и, если загрузка не проходит, вариант загрузчика `ATmega328P (Old Bootloader)`.

На самой плате доступны крупные монтажные отверстия `5V` и `GND`. Для первого стендового теста одной сервы допустимо подключить к ним:

| Провод сервы | Контакт Nano |
| --- | --- |
| красный | `5V` |
| коричневый | `GND` |
| оранжевый | `D9` |

При таком временном подключении Nano должен питаться **только от сетевой USB-зарядки или power bank**, а не от USB-порта компьютера. Питание сервы проходит через элементы защиты и дорожки Nano, поэтому это не является окончательной силовой схемой: использовать только один сервопривод, только базовый ход `1400–1600 мкс` и остановить тест при перезагрузке Nano, мигании OLED или отключении USB-источника. Для постоянного тестера питание сервы нужно вынести отдельной ветвью от того же 5-вольтового источника.

## Датчик трубки Пито

По маркировке платы и корпуса это **Matek ASPD-4525**. На нём установлен цифровой дифференциальный датчик давления **TE Connectivity 4525DO-DS5AI001DP**: диапазон ±1 PSI (±6,895 кПа), I²C, 14-битный АЦП. Плата питается от 4 до 5,5 В и потребляет около 5 мА. Заводской адрес I²C — `0x28`.

Подключение к Arduino Nano (ATmega328P, 5 В):

| ASPD-4525 (JST-GH-4P, порядок Matek) | Arduino Nano | Назначение |
| --- | --- | --- |
| `5V` | `5V` | питание датчика, 4–5,5 В |
| `SCL` | `A5` | шина I²C тактирования |
| `SDA` | `A4` | шина I²C данных |
| `G` | `GND` | общая земля |

Не подключать плату к 3,3 В: данный экземпляр рассчитан на 5-вольтовое питание. Обе силиконовые трубки должны быть без заломов и утечек. Перед тестом оба порта должны находиться в неподвижном воздухе: прошивка усредняет первые 20 измерений и использует их как нулевое дифференциальное давление. Для функциональной проверки можно кратко подуть в трубку полного давления — `dP` и `V` должны заметно измениться.

## Сервопривод

По маркировке и размерам это **KST X10 V8.0** — цифровой тонкий сервопривод для крыла с coreless-мотором. Допустимое питание 4,8–8,4 В (номинально 7,4 В); управляющий вход принимает логический уровень 3,3–5 В. Рабочая частота — 333 Гц, типовые команды: 1000 / 1500 / 2000 мкс соответствуют −50° / 0° / +50°. Проводка стандартная:

| Провод KST X10 | Подключение | Назначение |
| --- | --- | --- |
| оранжевый | `D9` Arduino | PWM-команда |
| красный | внешний стабилизированный источник 4,8–8,4 В | `V+` сервы |
| коричневый | земля источника и `GND` Arduino | `GND` |

Красный провод **нельзя** питать от вывода Arduino Nano или USB: серва может потреблять импульсный ток, существенно превышающий возможности платы. Для теста нужен отдельный BEC/лабораторный источник с запасом по току; общая земля с Nano обязательна.

### Универсальный сценарий теста сервы

Тестер не знает, установлена ли серва на левом или правом крыле, и не назначает физическое направление движения. Положение зависит от ориентации сервы, тяги и настройки реверса в полётнике. Поэтому интерфейс показывает только **абсолютную длительность PWM-импульса**, а не «лево» или «право».

| Режим | Последовательность | Статус |
| --- | --- | --- |
| Базовый тест | `1500 → 1400 → 1600 → 1500 мкс` | реализован по умолчанию |
| Расширенный тест | `1500 → 1200 → 1800 → 1500 мкс` | запускать только после проверки механического хода |

Базовый диапазон `1400–1600 мкс` намеренно мал: до первого запуска надо отсоединить тягу либо убедиться, что механика имеет свободный ход. Для подключённого Kakute H7 Wing считаны рабочие пределы крыльевых серв: `SERVO2` и `SERVO3` используют `1200–1800 мкс`, нейтраль `1500 мкс`, с реверсом на обоих выходах; расширенный режим не должен выходить за эти значения. Рабочая частота полётного контроллера — 200 Гц.

Сервопривод не даёт в контроллер телеметрию положения, поэтому успешный результат означает, что тестовая команда отработана; фактическое движение оператор подтверждает визуально. Обрыв красного/коричневого/оранжевого провода по этой трёхпроводной схеме автоматически диагностировать нельзя.

## Экран

На фото — OLED **0,96″, 128×64, I²C** с выводами `GND`, `VCC`, `SCL`, `SDA`; по маркировке `0x78/0x7A` это наиболее вероятно SSD1306. Указанные на плате значения — восьмибитная форма адреса, поэтому при работе через Arduino `Wire` реальный семибитный адрес будет `0x3C` либо `0x3D`.

Для этого тестера выбран **I²C-экран**, а не имеющийся SPI-вариант:

- он использует только два сигнальных вывода Nano (`A4` и `A5`), уже занятые шиной датчика Пито;
- ASPD-4525 имеет адрес `0x28`, поэтому конфликта адресов с экраном нет;
- скорость отрисовки меню и показаний не критична, возможностей I²C достаточно;
- SPI остаётся свободной для будущего LoRa-модуля, который обычно подключается через SPI.

| OLED I²C | Arduino Nano |
| --- | --- |
| `GND` | `GND` |
| `VCC` | `5V`* |
| `SCL` | `A5` |
| `SDA` | `A4` |

\* Перед окончательной пайкой проверьте маркировку конкретного модуля: большинство таких плат имеют стабилизатор и допускают 5 В, но OLED без преобразователя уровней может требовать 3,3 В. Сначала выполните I²C-сканер при безопасном питании; он должен обнаружить экран по `0x3C` или `0x3D` и ASPD-4525 по `0x28`.

## Прошивка и органы управления

Скетч расположен в [`firmware/wing_tester/wing_tester.ino`](../firmware/wing_tester/wing_tester.ino). Он рассчитан на OLED SSD1306 128×64 по I²C и библиотеку **U8g2**. Экран разделяет с ASPD-4525 ту же I²C-шину (`A4`/`A5`); адреса не конфликтуют (датчик `0x28`).

| Орган управления | Пин Nano | Подключение |
| --- | --- | --- |
| Вверх | `D2` | кнопка между пином и GND |
| Вниз | `D3` | кнопка между пином и GND |
| OK | `D4` | кнопка между пином и GND |
| Назад / отмена | `D5` | кнопка между пином и GND |

Включены внутренние подтягивающие резисторы, поэтому внешние подтяжки кнопок не требуются. Для сборки выберите **Arduino Nano / ATmega328P**, установите библиотеку `U8g2`, затем загрузите скетч. Если I²C-сканер обнаружит экран как `0x3D`, измените `kOledI2cAddress8bit` на `0x3D << 1`; если контроллер окажется не SSD1306, замените единственную строку создания `display` в начале скетча.
