# Быстрый тест ASPD-4525: 10 секунд при 400 кГц

Скетч: `firmware/aspd_4525_test/aspd_4525_test.ino`, Arduino Nano / ATmega328P. Требуется библиотека **U8g2** от oliver.

## Как проверить

1. Подключить датчик короткими исправными проводами: 5V, GND, A4/SDA, A5/SCL. Полётник отключить. OLED можно оставить на общей шине.
2. Загрузить скетч и открыть Serial Monitor на **115200 бод**. Открытие монитора может перезапустить Nano.
3. Оставить оба штуцера при одинаковом давлении. Скетч выполняет один прогон: **10 секунд при I²C 400 кГц, 200 чтений/с**, затем прекращает опрос. Для повторного прогона нажать RESET.
4. Сохранить полный журнал с `BEGIN`, `DATA` и `END` за полный 10-секундный прогон. Повторить с исправным датчиком на той же проводке. При замене датчика отключить питание и начать новый журнал с его номером.

OLED показывает только статическую заставку. Во время измерений к нему нет обращений, скорость/температура доступны в Serial. Экран остаётся электрически подключённым к шине. При необходимости сравнить оба датчика также без OLED, отключая его при выключенном питании.

Каждый режим начинает отдельную статистику и калибровку нуля по первым 10 успешным измерениям. При каждом `BEGIN` давление должно быть одинаковым на обоих портах. После обрыва внутри режима ноль не меняется. Частота шины и частота опроса — разные величины; этот тест не гарантирует точного воспроизведения протокола конкретного полётника.

## Что смотреть

Пример обозначения начала режима: `BEGIN bus_khz=400 target_hz=200 duration_ms=2500`.

`DATA` — снимок приблизительно раз в секунду. `END` — итог прогона, после которого опрос останавливается. Все счётчики относятся к текущему прогону. Заставка OLED остаётся неизменной; завершение видно по строке END в Serial.

| Поле | Значение |
| --- | --- |
| `khz`, `ms` | Частота I²C и время от начала режима |
| `poll_hz`, `good_hz` | Фактическая частота всех попыток и успешных измерений за последний отчётный интервал |
| `n`, `ok` | Всего попыток и корректных измерений с начала режима |
| `bus` | Ошибки обмена, неполные пакеты и тайм-ауты |
| `stale`, `fault`, `bad` | Устаревшие данные, диагностическая ошибка датчика, другой ненулевой статус |
| `timeout` | Тайм-ауты Wire; входят в `bus`, не прибавлять второй раз |
| `drops` | Число серий неуспешных чтений |
| `missed` | Пропущенные тестером интервалы по 5 мс; не ошибка, присланная датчиком |
| `late_us`, `read_us` | Максимальная задержка старта относительно расписания и максимальная длительность чтения, мкс |
| `valid` | Последнее чтение корректно; не заключение об исправности датчика |
| `age_ms`, `gap_ms` | Возраст последнего корректного измерения и максимальная пауза без него, включая текущую; до первого успеха считается от начала режима |
| `same_max_ms` | Максимальная наблюдавшаяся длительность серии корректных чтений с одинаковым кодом давления; ошибки прерывают серию |
| `result` | 0: успех; 1: ошибка обмена; 2: stale; 3: fault; 4: другой статус |
| `st`, `rx` | Статус пакета и число принятых байтов; st=255: статус не получен |
| `raw`, `rawT` | Последние корректные исходные коды давления и температуры |
| `span`, `wn` | Размах кода давления и число успешных измерений за последний отчётный интервал; при wn=0 span неинформативен |
| `z` | Число измерений калибровки; z=10: ноль готов |
| `zero10`, `P10`, `dP10` | Поправка, давление до/после коррекции, в десятых Па: **делить на 10** |
| `T10` | Температура в десятых °C: **делить на 10** |
| `V10`, `Vr10` | Скорость с коррекцией / без коррекции нуля в десятых м/с: **делить на 10** |

Например, `P10=2131` означает 213,1 Па, `T10=237` — 23,7 °C. До первого успешного пакета числовые измерения равны нулю; при valid=0 они не являются актуальными. dP10/V10 информативны только после z=10. Скорость вычисляется из модуля давления, поэтому для диагностики направления использовать давление со знаком. Пересчёт рассчитан на дифференциальную версию ±1 PSI с характеристикой 10–90%.

## Как интерпретировать

- Сравнивать итоговые `END` для одинаковой частоты шины у подозрительного и исправного экземпляров. За 10 секунд ожидается около 500 попыток, если тестер выдерживает расписание.
- Если `poll_hz` около 200, но `good_hz` ниже, смотреть `bus/stale/fault/bad`. 200 чтений не гарантируют 200 новых измерений.
- Если растёт `missed` или сам `poll_hz` существенно ниже 200, режим не выдерживает тестер/обмен. Проверить `read_us`, `late_us` и тайм-ауты; не приписывать все задержки датчику автоматически.
- Повторяющиеся ошибки только на подозрительном экземпляре при одинаковой сборке — воспроизводимый признак проблемы этого экземпляра в данном режиме. Ошибки обоих датчиков требуют проверки стенда.
- Постоянное значение давления в покое, отдельное 0.0 Па и стабильная температура не являются достаточными признаками брака. Проверка чувствительности требует контролируемого изменения давления, проверка точности — эталонного манометра.

Реализация выполняет одно чтение на попытку без повторов, не запускает серию догоняющих чтений после задержки, передаёт Serial небольшими порциями только при наличии места в UART. Формирование строки всё же занимает процессорное время; его влияние видно в фактической частоте и счётчиках задержек. На реальном стенде обязательно проверить эти показатели.

Короткий тест предназначен для воспроизведения обнаруженных массовых ошибок на 400 кГц. Нулевые ошибки за 10 секунд не исключают редкие сбои и не подтверждают точность датчика.
